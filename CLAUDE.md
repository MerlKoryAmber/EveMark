# CLAUDE.md — метод работы с агентом (EveMark)

Правила репозитория выше привычек агента. Конфликт с общим гайдом — репо побеждает, конфликт назвать, не молчать.

Взято из [squid-panel/CLAUDE.md](https://github.com/MerlKoryAmber/squid-panel/blob/main/CLAUDE.md). Не перенесено: лаба, `scp`, Squid, keytab, `CODEMAP`, меню вопросов. Карта здесь — `docs/SKELETON.md`.

## 1. Роли

Проектировщик, строитель, проверяющий, приёмщик — разные. Автор себе «принято» не ставит.

## 2. Пайплайн крупной задачи

АУДИТ → ПЛАН (согласовать до правок) → РЕАЛИЗАЦИЯ ровно по плану → ВЕРИФИКАЦИЯ не автором → ПРИЁМКА человеком. «Заодно» не делать.

Статусы: НЕ НАЧАТА → В РАБОТЕ → РЕАЛИЗОВАНО НО НЕ ПРИНЯТО → ПРИНЯТО → ЗАБЛОКИРОВАНО.

## 3. Доводить до конца

Перед «готово» — сверка с формулировкой попунктно. Хвост назвать и записать в скелет. Молчаливых хвостов нет. «Готово» без проверки по фактам нельзя.

## 4. Проверка по фактам

Код. Секреты и живая база не в git и не в отчёт. UI — живой сценарий в браузере, не один скриншот. Числа сырые: сколько строк, какой ответ API. Пустое поле — не «чисто». Проверка, которая не может провалиться, — не проверка. Приёмка — человеком.

Диагностика стола: данные → API → отрисовка → разметка → стили. Редизайн последним.

## 5. Данные

Массовая правка базы: baseline → dry-run → бэкап → apply → сверка до/после. `publish\data` не удалять и не затирать публикацией.

## 6. Git

Точечный `git add`, никогда `git add .`. Ветки `feature/` и `fix/`. В `main` и push — только по команде. Force-push нельзя. Секреты, `.env`, базы, `publish/`, `data/` не коммитить.

Коммит — только если человек явно попросил. Push предлагать отдельным шагом, не вместе с коммитом.

Перед push обновить `docs/SKELETON.md`, если менялись структура, схема, пороги или запуск.

## 7. Коммиты не терять

Работа доходит до `main` по команде человека или явно списана. Слепой `stash pop` нельзя.

## 8. Параллельные сессии

Перед правками смотреть статус ветки. Общие номера ADR не занимать молча.

## 9. Конфликт

Ветка `reconcile/<задача>`. `main` не трогать. Итог — предложение. Две живые реализации одного поведения не оставлять. Слияние не вышло — статус ЗАБЛОКИРОВАНО.

## 10. Документы важнее памяти

Порядок до правок: `CURSOR_HANDOFF.txt`, затем `docs/SKELETON.md`, затем ADR по ссылке из скелета, затем точечное чтение кода. Сплошной поиск папок запрещён, если человек не назвал файл.

Человеческие тексты («зачем программа», `docs/OPISANIE.md`, развёрнутое «что умеет»): писать **из скелета и прочих docs**, не собирать заново из UI/кода. Код — только сверка; дыра в доках — закрыть в docs в том же шаге.

Не записано — решения нет. Структуру, схему, пороги и запуск обновлять в скелете в том же шаге. Ниже ПРИНЯТО итог в доки не фиксировать как принятый. «Запомнил» в чате без файла в docs/store — не считается.

## 11. Отчёты

Один промпт — один шаг. Полный отчёт — `docs/agent_reports/<задача>/REPORT.md`. В чат 5–8 строк.

## 12. Субагенты

Простую правку не дробить. Верификация не автором, широкий аудит, независимые ветки — да. Субагент задачу не принимает.

## 13. Стиль

Ответы кратко, без воды, связными фразами. Код, команды, имена, ошибки — дословно. Коммиты: Conventional Commits, тип латиницей, текст после `:` по-русски.

Телеграфные обрывки из SPM сюда не входят: в этом чате нужны нормальные предложения. Предупреждение о необратимом — обычным языком.

## 14. Скиллы

Подходящий скилл прочитать до первого действия. Этот файл и указания владельца выше скилла.

## 15. Вопросы

Не на каждый шаг. Формы с вариантами запрещены. Спрашивать только при блоке: push, удаление, необратимое. Иначе делать и писать статус.

SPM требует меню с последствиями. Здесь это не применяется: владелец запретил.

## 16. Не придумывать

Сначала handoff и скелет, потом код. Пороги брать из скелета и кода (`SignalRule`, `FeeMath`, `CollectorService.IsCosmetic`). Штатная библиотека лучше самописной.

## 17. Без спроса и со спросом

Без спроса: локальная сборка, тесты, чтение ESI. Со спросом: push, удаление базы, отправка наружу.

## 18. Уборка

Свои временные каталоги удалять. `publish\data` и файлы пользователя не трогать.

## 19. Приёмка

«Принято» ставит только человек.

## 20. Время

МСК (UTC+3). Чужое время перевести и подписать: `14:20 МСК (11:20 UTC)`.

## Проект

Локальный стол Jita 4-4. Ордера только читаются. Каталог `C:\Code\jita-watch`. Репозиторий https://github.com/MerlKoryAmber/EveMark. Живое: `publish\JitaWatch.exe`, `http://127.0.0.1:8741`, база `publish\data\jita.db`. Сборка самодостаточная, Windows x64. Карта запуска и правил рынка — в скелете.
